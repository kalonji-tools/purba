# The rules of this form (prototype of #980, on the prototype of #979)

A prototype test form, run by its own small runner: `python run.py [file or folder …]`. A tester imports `case`, `raises`, `warns`, `handling`, `use` and `before_each` from `cases.py`, and only when a test needs them.

- **A test is a plain function named `test…` in a file named `test_….py`, and its checks are the asserts at its end.** Its parameters are its inputs. The act is everything before the first check: **the act ends at the first check**, and only checks follow it. A test whose parameters all have a default, or that has none, runs once under its own name. A `return` may follow the checks; it hands a product to a later case (see the chain below).
- **The act has one path in each case, and the runner sees it while the case runs.** Each line of the act runs in every case, each branch in it (`if`, `x if c else y`, `and`, `or`, `while`, `except`) goes both ways in a case or is not there, and each loop runs at least one round. A loop over any data is fine: `for t in threads: t.join()`. A case that breaks this is refused, and the runner names the line.
  - The act is the test's own code that the test calls: the test, a function or class of its file or of its folder, and what those call in turn. A function of the test's own that **the code under test calls** (a callback, a format function, a sink) is a value: its paths are free. Who calls it decides, not how it was handed over.
  - An `assert` that runs anywhere in the test's own code before the checks is refused, in a helper or a callback too: the act ends at the first check, and the code under test may swallow an assert.
  - A `raise` may sit in the act. A setup that swallows it at its last line passes; any other raise ends the act.
- **A `with` in the act is a setup:** what it sets up holds for the statements inside it, and is undone when they end, as `with freeze_time("2001-02-03"):` or `with mock.patch.object(sys, "stderr", None):`. A setup may hold several items, or another `with`.
  - **The checks may sit at the end of a setup, after it, or both.** Checks at the end of a setup read under it; checks after it read once it is undone.
  - A setup that swallows a raise (such as `contextlib.suppress`) fails the case when a statement inside it never ran because of it. A raise in its last statement may be swallowed: that is what such a setup does.
  - A setup whose own entry or undo raises fails the case, and names it.
- **Three `with` blocks of the form each wrap one statement, and each takes a `with` of its own:**
  - `with raises(SomeError, match=r"…") as caught:` expects a raise. It ends the act: a line of the act that runs after it caught is refused. The checks may read `caught.value`, the exception. `as caught` is optional.
  - `with warns(SomeWarning, match=r"…"):` expects a warning, anywhere in the act.
  - `with handling(SomeError, call, *args):` is for code that must run inside an `except`, such as `logger.exception`. It fails the case unless the statement raises `SomeError`, and then runs `call(*args)` while that exception is live.
- **A check is one comparison: `assert reading == expected`, or with a message, `assert reading == expected, "what it checks"`.** Any one operator: `==`, `!=`, `<`, `<=`, `>`, `>=`, `in`, `not in`, `is`, `is not`. One side is the expected value: a literal, operators on literals (`"7" * 20 + "\n"`), an input of the test, or a list, tuple, set or dict of these. The other side reads what the act made, and may compute (`writer.read().splitlines()[0]`).
  - A failure names the check by its own text, and prints the message under it if there is one.
  - Every check runs, even after another fails. The checks read in place, in order, and each check after the first is also read alone, in a fork taken before any check read. A check that holds alone and fails after the checks before it, or the other way round, is refused: a reading before it changed what it reads, and a check reads, it does not act. Call the code in the act, `wrapped = should_wrap(stream)`, and check `wrapped`. The runner compares, so `python -O` changes nothing.
  - `==` compares by type, then by value: the reading must be an instance of the expected value's type (a subclass of `str` is a `str`), except that `True` is never `1` and `1.0` is never `1`. Lists, tuples and dicts are compared item by item. Other operators work as in Python.
  - A check that reads only an input holding a `str`, a number, a `bool`, `bytes`, `None` or a tuple is refused, because the act cannot change it.
- **A case is `name = case(test, input=…, …)` at module level, named by its variable.** Each input is named; a parameter with a default may be left out. A type checker reads the call against the test's parameters, so it sees a misspelled input, a missing input, and an input of the wrong type. The runner checks each input's type too, when it can read the annotation at run time; it cannot read a name that only a type stub declares. An input that a check uses as its expected value takes a literal in every case.
- **To pass a value of the wrong type on purpose,** declare the input `object`. The one line of the act that breaks a type carries the checker's coded ignore, so the case lines stay checked.
- **A fixture is the default of an input, `use(factory)`:** `writer: Writer = use(Writer)`. The runner calls `factory()` again for each case, and a case may pass its own value instead. A value the test can build in one line may simply be built in the act.
- **`before_each(fn)`, at module level, runs `fn()` at the start of each case of that file,** such as a reset of a library's global state. Nothing runs after a case: its process ends, and what it changed ends with it.
- **A stock is an input whose state lives outside the process,** such as a database file. Its fixture subclasses `Samples[T]` (`sample()` for each case, `discard(value)` after it), `Checkpoints[T, M]` (`open()`, `checkpoint(value)`, `restore(value, mark)`), or both, and a test takes it as `db: Db = use(UsersDb)`. For each check, the fixture also subclasses `Fingerprints[T]` (`fingerprint(value)`) or `Checkpoints`, and a stock that offers neither is refused before the run. The runner takes the fingerprint before and after each check, or else sets a checkpoint and restores it. A check whose reading changed a stock is refused, through whatever name it read it.
- **A chain:** a later case takes `earlier.product` as an input, where the earlier test ends with `return value`. The runner runs the earlier case again first, with its checks, once for each later case. If it reads differently, the later case is blocked.
- **Each case runs in a forked process of its own,** so nothing a case does reaches another. Output a case prints is shown only when it fails. An open file, socket, pipe or `mmap` that two checks read is refused, because a fork cannot seal it. A warning that the test does not expect fails the case, and so does an error that no code sees (in a thread, or in a finaliser).
- **The act may not replace a hook that the runner sees a fault through:** `threading.excepthook`, `sys.unraisablehook`, the warning filters (`warnings.simplefilter`, `catch_warnings`, …) and the time limit (`signal.alarm`, a `SIGALRM` handler). A hook that is not the runner's own while a line of the test runs fails the case, and names the line that replaced it, even when a later line puts it back. A library that replaces one and puts it back inside a single call of the test is not seen. `sys.stdout` and `sys.stderr` are free: the runner prints through a stream of its own. To expect a warning, use `warns`.
- **The runner runs each test as written.** It imports a test file with each test's checks rewritten as checks of its own, as pytest rewrites an assert. Called by hand, a test is a plain function, and its asserts are Python's.
- **The runner refuses, before the run, what it reads from the code:** a check in another form, a computed expected value, a check that reads only a value the act cannot change, a `global`, `nonlocal`, `yield`, `await` or `async with`, a `with` inside a loop or another block, and a test with a decorator. A refusal names every fault at once. A fault of a test stops its cases.
- **The runner refuses, after the import:** a misspelled or missing input (with a hint), an input of the wrong type, an input by position, a case that no module name holds (bound again later, built by a loop, never bound), and a case that two names hold. It reads the names from the module, not from the source.
- **The runner refuses, while the case runs:** a path of the act that a case did not take, an assert in the act, a line after an expected raise, a check whose reading changed what a later check reads or changed a stock, and a case in which no check ran. A refusal is the test's fault; a failure is the code's.
- **The run ends with a count,** `N cases: … passed · … failed · … refused · … blocked`, and exits 1 unless every case passed. A case with a refusal counts as refused, even if a check also failed.
