# The rules of this form

A prototype test form, run by its own small runner: `python run.py [file or folder …]`. A tester imports `case`, `raises`, `warns` and `use` from `cases.py`, and only when a test needs them.

- **A test is a plain function named `test…` in a file named `test_….py`.** Its parameters are its inputs. A test whose parameters all have a default, or that has none, runs once under its own name.
- **The body is the act, then the checks.** The checks are the asserts at the end of the body. Everything before them is the act. A `return` may follow the checks; it hands a product to a later case (see the chain below).
- **The act is a straight line.** Any statements and calls, in order, with literals, nested calls, lambdas, and functions or classes defined inside the test. Nothing inside a test, its own functions and lambdas included, holds an `if`, `x if c else y`, `and`/`or`, `match`, a loop, a comprehension, `raise`, `global`, `yield` or `await`, or an `assert` before the end. Two forms are allowed, because the runner proves which path ran:
  - `try:` with one statement, then one `except SomeError:` with straight-line code, and no `else` or `finally`. When the body does not raise `SomeError`, the case fails: its `except` never ran.
  - `with raises(SomeError, match=r"…"):` around one statement, as the last statement of the act; `with warns(SomeWarning, match=r"…"):` around one statement, anywhere in the act. Any other `with` is refused.
- **A check is `assert reading == expected`, or `assert reading == expected, "what it checks"`.** The reading is on the left. The expected value is a literal, an input of the test, or a list, tuple, set or dict of these. The message, if any, is printed with a failure.
  - Every check runs, each in a process of its own, even after another fails. The runner compares, so `python -O` changes nothing.
  - A reading is compared by type, then by value. It must be an instance of the expected value's type (a subclass of `str` is a `str`), except that `True` is never `1` and `1.0` is never `1`. Lists, tuples and dicts are compared item by item.
  - A check reads what the act made or changed. A check that reads only an input holding a `str`, a number, a `bool`, `bytes`, `None` or a tuple is refused, because the act cannot change it.
- **A case is `name = case(test, input=…, …)` at module level, named by its variable.** Each input is named; a parameter with a default may be left out. A type checker reads the call against the test's parameters, so it sees a misspelled input, a missing input, and an input of the wrong type. An input that a check uses as its expected value takes a literal in every case.
- **To pass a value of the wrong type on purpose,** declare the input `object`. The one line of the act that breaks a type carries the checker's coded ignore, so the case lines stay checked.
- **A fixture is the default of an input, `use(factory)`:** `writer: Writer = use(Writer)`. The runner calls `factory()` again for each case, and a case may pass its own value instead. A value the test can build in one line may simply be built in the act.
- **A stock is an input whose state lives outside the process,** such as a database file. Its fixture subclasses `Samples[T]` (`sample()` for each case, `discard(value)` after it), `Checkpoints[T, M]` (`open()`, `checkpoint(value)`, `restore(value, mark)`), or both, and a test takes it as `db: Db = use(UsersDb)`. A check that reads a stock runs between a checkpoint and a restore; with no checkpoint, two checks that read one stock are refused.
- **A chain:** a later case takes `earlier.product` as an input, where the earlier test ends with `return value`. The runner runs the earlier case again first, with its checks, once for each later case. If it reads differently, the later case is blocked.
- **Each case runs in a forked process of its own,** so nothing a case does reaches another, and global state needs no reset. Output a case prints is shown only when it fails. An open file, socket, pipe or `mmap` that two checks read is refused, because a fork cannot seal it.
- **A warning that the test does not expect fails the case,** and so does an error that no code sees (in a thread, or in a finaliser).
- **The runner refuses, before the run:** logic in a test, a check in another form, a test that checks nothing, a computed expected value, a misspelled or missing input (with a hint), an input of the wrong type, an input by position, a case with no name, a case name bound twice, cases built by a loop, and a test with a decorator. A refusal names every fault at once. A fault of a case stops only that case; a fault of a test stops its cases.
- **The run ends with a count,** `N cases: … passed · … failed · … refused · … blocked`, and exits 1 unless every case passed.
